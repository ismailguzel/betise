# BeTiSe reproduction package 1.0.0

This package defines how to generate **120,000 new univariate time series** with
BeTiSe **0.6.1**. It accompanies the existing dataset record
https://doi.org/10.5281/zenodo.18513505 and paper https://doi.org/10.3390/cmsf2026016024.
It does not reproduce the old numerical series or the paper's reported experiments.

## Install

Tested with Python 3.11 on Linux and macOS. From the extracted package root:

```bash
python3.11 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

The package pins the published BeTiSe release and its tested dependencies. It does
not modify the installed library. Use a new output directory for each profile/run.

## Generate

First run a 240-series smoke test:

```bash
python datasets/zenodo-v2/prepare.py --profile pilot --output generated/pilot
python datasets/zenodo-v2/run.py generated/pilot --keep-going
```

For a broader 7,680-series validation covering the selected categorical recipes:

```bash
python datasets/zenodo-v2/prepare.py --profile validation --output generated/validation
python datasets/zenodo-v2/run.py generated/validation --keep-going
```

Generate the full 120,000-series dataset when local checks and storage allow:

```bash
python datasets/zenodo-v2/prepare.py --profile candidate --output generated/dataset
python datasets/zenodo-v2/run.py generated/dataset
```

The full target is 40,000 per length group: 20,000 stationary and 20,000 non-stationary
under the documented generation-label convention. Each of 120 jobs has 1,000 series;
selected categorical recipes share this count. See `datasets/zenodo-v2/scope.json`
and `datasets/zenodo-v2/PRODUCTION_PLAN.md` for the complete allocation and representative coverage.

Short Fourier-seasonal jobs explicitly use periods 7 (single) or 3 and 7 (multiple).
These choices preserve lengths 50–100 and the library's six-cycle requirement.
They are dataset-specific numerical settings, not changes to BeTiSe's published
parameter defaults. The managed runner applies them and records their provenance.
Running only the native config CLI would not apply these manifest-level overrides.

## Outputs and checks

Each job writes complete series into Parquet shards and records its config, seed,
recipe counts and summary. The runner verifies lengths/time order, finite values,
composition metadata, declared stationarity flags and exact per-recipe counts.
Logs, environment versions and file hashes are stored beside the output. Rerun the
same command to verify and skip completed jobs; incomplete outputs are never deleted
automatically. Do not change the environment or code midway through a run.

Numeric `series_id` restarts per job. Use `(job_id, series_id)` as the global identity
when joining files, and keep complete series together in any benchmark split.
Use only observations or deliberately selected covariates as model input; metadata
can directly reveal the target or generation parameters.

## Inspect the included example

`examples/sample-series.parquet` contains six synthetic series from the smoke pilot,
with `source_job_id` and `series_uid` added to prevent ID collisions:

```python
import pandas as pd

sample = pd.read_parquet('examples/sample-series.parquet')
print(sample.groupby('series_uid').size())
series = sample[sample['series_uid'] == sample['series_uid'].iloc[0]]
series.sort_values('time').plot(x='time', y='data')
```

## Scope of validation

The included validation report records the actual checks performed. Passing
structural or generation-label checks is not proof of empirical stationarity,
complete categorical coverage of the library, or real-world representativeness.
No classification results from the paper have been rerun. All historical-data
counts and differences are kept separate from this new 120,000-series specification.

`MANIFEST.json` contains SHA-256 hashes for the distributed files. Generated bytes
may differ across platforms despite a fixed seed; numerical dependency versions,
Python version, scope and code must also be recorded.
